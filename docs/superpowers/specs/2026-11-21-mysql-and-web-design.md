# 실제 MySQL 검증과 웹 면접 화면

## 승인 및 목표
사용자는 2026-11-21에 실제 MySQL 검증 후 커밋, 웹사이트 구현 후 별도 커밋을 요청했다.
추가 질문에서 기존 Spring 서버가 한국어 웹 화면을 함께 제공하는 구성을 선택했다.
이 문서는 그 범위를 기록하며 운영 배포·유료 API·실제 AI 추가 호출은 포함하지 않는다.

## 1. 실제 MySQL 검증
- 기존 DB 대신 별도 MySQL 8.0 컨테이너·임시 데이터 영역을 사용한다. 기존 컨테이너/볼륨은 건드리지 않는다.
- 구형 스키마와 가상 데이터를 준비한 뒤 현재 수동 SQL을 적용한다. 과거 행·점수·중복 답변이 보존되는지 검사한다.
- Hibernate `ddl-auto=validate`로 마이그레이션 결과를 검사한다. 자동 update/create로 검증을 우회하지 않는다.
- JWT 인증 → 이력서 저장 → 질문 5개 → 최초/꼬리 답변 평가 → 완료 → 기록 재조회를 검증한다.
- 소유권 차단, 한글/보조 평면 문자, 원자성·동시 제출·완료 중 늦은 결과를 기존 흐름 테스트와 함께 검사한다.
- AI는 로컬 HTTP 스텁을 사용한다. 실제 Groq 요청 및 사용자 이력서는 사용하지 않는다.
- 기본 테스트는 H2를 유지한다. MySQL 테스트는 명시적인 전용 URL이 있을 때만 실행한다.
- 완료 후 자신이 만든 컨테이너만 정리하고 재현 스크립트와 결과를 커밋한다.

## 2. 웹사이트
### 접근 방식
- 선택: Spring 정적 HTML/CSS/JavaScript. 같은 출처 API이므로 별도 빌드·CORS·서버가 필요 없다.
- 대안: 별도 React 앱은 향후 확장에 유리하지만 현재 최소 화면에는 빌드/배포 구성이 불필요하게 늘어난다.
- 기존 API와 데이터 모델을 유지하고 공개 정적 경로만 허용한다. API 인증·소유권은 서버에서 계속 강제한다.

### 사용자 흐름
1. 회원가입/로그인. 토큰은 메모리에만 보관하며 새로고침 시 다시 로그인한다. API 키는 브라우저에 전달하지 않는다.
2. 이력서 텍스트 입력 또는 기존 이력서 선택. 20,000 코드 포인트 한도·저장/AI 전송 안내.
3. 사용자가 면접 시작을 누르면 질문 5개를 생성하고 실제 저장된 세션을 연다.
4. 질문과 이력서 인용을 확인하고 답변을 제출한다. 평가 3축·강점·개선·불확실성을 한국어로 표시한다.
5. 꼬리 질문이 있으면 같은 기본 질문 아래에서 한 번만 답변한다. 과거 최초 평가와 종합 평가를 구분한다.
6. 완료 처리 및 세션 목록/기록 재조회. 진행 중 면접도 목록에서 이어갈 수 있다.

### 레이아웃과 시각 체계 (구현자 결정)
- 한국어 중심의 조용한 면접 작업 공간. 화이트 #FFFFFF, 연한 청회색 #F3F6FA, 진한 남색 #172B45,
  파란색 #235CB3, 녹색 #20634C, 오류 #AC303D. 보라색 그라데이션/장식 통계는 사용하지 않는다.
- 시스템 한국어 산세리프(`Apple SD Gothic Neo`, `Malgun Gothic`, sans-serif), 제목 32/24px, 본문 16px.
- 데스크톱: 왼쪽 질문 탐색, 중앙 질문·답변, 오른쪽 평가. 모바일: 세로 배치.
- 로그인 전에도 제품의 용도와 이력서 기반 면접 흐름을 이해할 수 있다.
- 입력은 실제 label, 키보드 포커스, 상태 알림은 aria-live, 작은 화면 가로 넘침 없음.

```text
[이력서 면접 코치]                           [로그아웃]
[이력서] [면접 기록]
[질문 1~5] | [이력서 인용 / 질문 / 답변 입력] | [항목별 평가]
           | [답변 제출 / 꼬리 질문]         | [강점 / 보완 / 불확실성]
```

### 경계 및 오류
- 로딩 중 중복 제출을 막는다. 실패 시 입력을 보존하고 자동 재호출하지 않는다.
- 인증 만료·세션 완료·중복 제출은 재로그인/기록 갱신 등 구체적인 행동을 안내한다.
- 사용자/AI 문자열은 textContent로 출력한다. innerHTML을 이용해 외부 데이터를 삽입하지 않는다.
- 로그아웃 시 토큰·이력서·답변 DOM을 비운다. 계정 변경 중 늦은 응답을 새 계정 화면에 반영하지 않는다.
- 면접 완료는 되돌릴 수 없음을 확인한다. 진행 중에도 기록 조회가 가능하다.

## 성공 기준과 비목표
- MySQL 8에서 마이그레이션+흐름 검증이 실제 통과하고 첫 커밋이 존재한다.
- 웹 인증/입력/평가/기록 흐름을 실제 브라우저에서 로컬 AI 스텁+DB로 검증하고 두 번째 커밋을 만든다.
- API와 정적 자원의 공개/보호 경계, XSS 문자열, 긴 텍스트, 재로그인 및 오류 후 재제출을 테스트한다.
- PDF/Word 업로드, 음성, 관리자, 배포, 비밀번호 재설정, 실시간 스트리밍, 추가 실제 AI 호출은 제외한다.
