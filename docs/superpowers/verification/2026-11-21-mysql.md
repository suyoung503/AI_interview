# MySQL 8 마이그레이션 검증 — 2026-11-21

- 실행: `scripts/verify-mysql.sh -o` (이미지와 Maven 의존성이 준비된 로컬 Docker 환경).
- 대상: 루프백 임시 포트의 전용 MySQL 8.0.46 / InnoDB. 검증용 DB는 매번 새로 만들며, 기존 DB·컨테이너·볼륨을 사용하지 않는다.
- 순서: 빈 스키마인지 확인 → 가상 구형 스키마와 데이터 삽입 → [저장소의 수동 SQL](../../../src/main/resources/db/migration/2026-11-20-resume-interview.mysql.sql) 실행 → Hibernate `ddl-auto=validate` → API·저장 테스트.
- 결과: **39건 통과, 실패·오류·건너뜀 0건**. MySQL Connector/J 연결과 Hibernate의 MySQL 8.0.46 메타데이터를 확인했다. SQL을 적용하지 않은 빈 MySQL에서는 `validate`가 `answers` 누락을 보고하고 시작을 중단했다.
- 보존: 가상 사용자·카테고리·완료 세션·고정 질문의 연결, 같은 질문의 답변 2건과 점수 60/90, 한국어 본문·피드백과 보조 평면 문자를 마이그레이션 뒤 확인했다.
- 신규 저장: 보조 평면 문자 20,000개를 이력서 저장 API에 보내고 별도의 조회 API에서 원문을 확인했다. MySQL의 저장 길이는 80,000바이트였다.
- 면접 흐름: JWT 로그인, 이력서 저장, 질문 5개, 최초/꼬리 답변 평가, 완료와 기록 재조회, 소유권 차단, 저장 실패 롤백, 동시 제출, 완료 후 지연 응답 차단을 같은 MySQL에서 검증했다.
- 기본 H2 회귀: 155건 집계, 134건 통과, 실패·오류 0건. MySQL 클래스에서 URL 미설정으로 18건, 실제 Groq opt-in 테스트 3건을 건너뛰었다(비활성화된 매개변수 테스트는 호출별로 확장되지 않음).
- AI는 로컬 HTTP 스텁만 사용했다. 실제 Groq 호출은 0회였다. 재현 스크립트가 만든 컨테이너와 익명 볼륨은 종료 시 제거한다.

이 검증은 가상 구형 스키마를 대상으로 했다. 실제 운영 스키마의 타입·문자셋·제약 차이, 백업 복원, 실데이터에 대한 운영 적용 시간이나 잠금은 확인하지 않았다.
