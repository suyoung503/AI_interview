## 잔여 한계와 미실행 범위

- **AI의 조건 설명은 완전하지 않다.** v4는 로컬 캐시 자동 동기화를 잘못된 주장으로 지목하고, Redis의 TTL 지원으로 ‘절대 만료되지 않는다’는 일반화를 반박했다. 그러나 TTL 설정/미설정 두 경우를 명시적으로 가르치지는 않았다. 기존의 ‘TTL 필수·모든 키 만료’라는 잘못된 일반화는 제거됐지만 이를 완전한 Redis 설명이나 모든 답변의 사실 정확성으로 일반화하지 않는다. 조건 확인의 기준은 [Redis EXPIRE 공식 문서](https://redis.io/docs/latest/commands/expire/)다.
- 모델은 권장 1~3개보다 많은 개선점을 줄 수 있다. 단일 샘플이나 15회 실행으로 전체 정확도·실패율을 추정할 수 없다. 평가 축 자체와 개인화된 강점·교정은 여전히 모델 판단이다.
- v4는 세 축이 모두 긍정일 때의 종료·결핍 억제와 축별 요약 일치를 서버가 보장한다. 이 정책이 선택적 심화 코칭까지 보여 주지는 않는다는 trade-off가 있다.
- **실제 MySQL 마이그레이션/격리·잠금 검증, Docker 빌드/기동·운영 배포는 하지 않았다.** 수동 SQL·사전 점검·백업 지침은 제공했으며 운영 적용은 별도 환경 검증이 필요하다. H2/패키징 성공을 운영 검증으로 대체하지 않는다.
- 미룬 경미 항목: 이력서 상세 비양수 ID는 404(세션 상세는400), 과거 점수 통계가 신규 평가도 읽은 뒤 제외하는 비용, 직렬화/긴 JVM 정지 후 타임아웃 오분류 가능성, 기준선 H2/Java 에이전트 경고. 저장 안전성과 정상 흐름에는 영향이 없다고 최종 리뷰에서 판단했다.
- 계획/설계의 실수로 남았던 선행 `+` 표시는 정리했다. 기존 private application.yml은 로컬에서 보존하고 배포 JAR에서는 제외한다.

## v4 구현 당시 실행한 최종 명령

```bash
env -u GROQ_API_KEY -u INTERVIEW_ENV_FILE ./mvnw -o \
  -Dspring.profiles.active=test \
  '-Dspring.config.location=classpath:application.properties,classpath:application-test.yml' \
  -Dgroq.live.confirmed=false -Dgroq.followup.diagnostic.confirmed=false \
  -Dgroq.technical.probe.confirmed=false test
./mvnw -o -DskipTests package
git diff --check
```

위 v4 최종 전체 실행은 2026-11-21에 134통과/3건너뜀/실패0/오류0 및 BUILD SUCCESS였다. 패키징도 BUILD SUCCESS이며 JAR 검사에는 파일명 목록만 사용했다. 건너뛴 실호출 테스트를 통과로 세지 않았다. 실제 검증을 다시 실행할 권한은 이 명령에 포함되지 않는다. 후속 코드 정리에서 테스트 설정은 `src/test/resources/application-test.yml`로, 남겨 둔 실제 AI 검증 및 보조 코드는 `com.interview.live`로 이동했다. 당시 증거와 집계는 그대로 보존한다.

## 구현 중 결정과 비용

1. 앱 관리 분리 HEAD에 로컬 커밋을 남겼다. 원본 main 제품 코드는 변경하지 않았으며 게시하려면 별도 브랜치/PR 작업이 필요하다.
2. H2 검증과 MySQL 운영 검증을 구분했다. 환경별 적용은 미확인 상태다.
3. 깨진 JSON은 전역으로 안전한 400을 반환하게 했다. 기존에 잘못 500을 받던 클라이언트는 상태가 달라진다.
4. 저장 테스트를 HTTP 테스트와 구분하고 OSIV를 껐다. 연관 DTO 조립은 서비스 트랜잭션 안에서 완료해야 한다.
5. 실제 모델 실패에 따라 Task7/8을 추가하고, 사용자 승인으로 공통 3축 및 단계별 모델 출력 계약으로 바꿨다. 추가 구현·검증 비용이 들었으나 원래 기능/완료 조건은 유지했다.
6. 충분한 평가의 결핍·꼬리를 억제하고 축별 요약을 서버가 소유하게 했다. 선택적 심화 의견은 억제될 수 있으나 이를 필수 보완으로 강요하지 않는다.

문서·증거 보존용 후속 커밋은 제품 코드를 바꾸지 않는다. 실행 방법과 API 예시는 프로젝트 [README](../../../README.md), 스키마 적용 안내는 [마이그레이션 문서](../../../src/main/resources/db/migration/README.md)를 참조한다.
