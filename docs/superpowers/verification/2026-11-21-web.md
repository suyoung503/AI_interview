- 브라우저 API 모듈: Node 22.1.0의 내장 테스트 러너에서 **11건 통과**. 보호 요청의 메모리 Bearer 토큰, 실패 시 무재시도, 보호 API 401/403과 로그인 실패 구별, 로그아웃·전환 뒤 헤더 또는 JSON 본문이 늦게 도착하는 응답 무시를 확인했다.
- 전체 Maven `verify`: test 프로필과 명시적인 테스트 설정, 로컬 HTTP 소켓으로 실행. **140건 통과 / 21건 건너뜀 / 실패·오류 0건**. 건너뛴 테스트는 별도 DB 또는 실제 호출을 명시해야 하는 opt-in 항목이다. 배포 JAR에 정적 자원 4개가 있고 `WebPreview`, `GroqStub`, 비공개 `application.yml`이 없음을 확인했다.
- 브라우저 환경: 루프백 Spring 미리보기와 수동 SQL 적용이 끝난 전용 MySQL 8.0.46(`ddl-auto=validate`). 가상 계정·입력과 로컬 HTTP AI 스텁만 사용했다. 실제 Groq 호출은 **0회**.
- 실제 브라우저 흐름: 회원가입·로그인, 이력서 저장과 태그 문자열의 평문 표시, 기본 질문 5개 탐색, 최초 평가와 꼬리 질문 제출 후 종합 평가를 확인했다.
- 브라우저 오류 복구: 로컬 평가 스텁으로 502를 내 초안이 남고 수정 후 재제출되는 것을 확인했다. 답변 저장 성공 직후 면접 상세 GET만 한 번 500으로 실패시켰을 때 재제출 버튼이 나타나지 않았고, **기록 새로 불러오기**로 저장된 답변과 평가를 확인했다.
- 완료 확인: 내장 브라우저에서 네이티브 확인창을 연 뒤 검증 도구 입력이 타임아웃됐다. 같은 화면의 두 단계 확인으로 변경하고 새 탭에서 취소 시 버튼으로 포커스가 돌아오며 초안이 남는 것, 확인 후 완료된 면접에 입력란이 없는 것을 재검증했다.
- 기록과 인증: 로그아웃 후 로그인해 완료된 기록에서 최초·종합 평가를 다시 확인했다. 새로고침 시 로그인 화면으로 돌아왔고, 저장한 이력서로 새 면접을 열 수 있었다. 지연 응답을 기다리는 동안 로그아웃해도 로그인 화면이 유지됐다. 응답과 로그아웃의 정확한 경합 순서는 Node 테스트에서 제어했다.
- 레이아웃: 데스크톱 1,280px과 모바일 390px에서 가로 넘침이 없었다. 모바일에서 질문 5개 탐색, 꼬리 답변 제출, 종합 평가와 면접 완료를 확인했다.
- 로컬 검증 스크린샷은 무시된 `target/web-screenshots/interview-desktop.jpg`와 `target/web-screenshots/interview-mobile.jpg`에 저장했다. 배포·운영 데이터·실제 AI 평가 품질은 이번 검증 범위 밖이다.
- 독립 리뷰 후 보완: 2xx 응답의 JSON 본문이 중간에 잘리거나 읽기 실패하면 목록을 덮어쓰지 않고 오류를 알린다. 직접 다시 조회하면 정상 복구한다. 이미 성공 상태를 받은 답변 제출과 완료 처리는 본문을 읽지 않고 상세 GET으로 확인한다. 회귀 테스트 4건의 실패를 재현한 뒤 수정하여 Node 전체 11건을 통과했다.
